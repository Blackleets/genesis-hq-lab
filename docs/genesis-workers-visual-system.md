# Genesis Workers — Visual System Specification

Genesis HQ is **not a game**. The office is a *living dashboard*: every pixel
reflects real internal AI work. This document defines the **Genesis Worker**
visual identity, the department system, the animation logic, and how it all
plugs into the existing live data — with a hard rule: **same colors, same dark
background, break nothing.**

> Visual reference (open in a browser, it animates):
> [`assets/genesis-workers-preview.svg`](../assets/genesis-workers-preview.svg)
> Regenerate with `node scripts/genWorkerPreview.mjs`.

## 1. What changed (and what did not)

| | Before | After |
|---|---|---|
| Worker art | Borrowed office PNG sprites (Kenney / "free office pixel art") | **Original Genesis Workers** drawn 100% from SVG `<rect>` primitives |
| Identity | Generic NPCs, no brand | Branded mascots, department color-coded, memorable |
| Animation | Static frame swap | 9 premium CSS states (idle → celebrating) |
| Colors | Existing token palette | **Identical token palette** — nothing new introduced |
| Background | `#0a0c12` dark HQ | `#0a0c12` dark HQ (unchanged) |
| Office layout, rooms, data flow | — | **Untouched** |

Only the *character renderer* was replaced. Positions, rooms, halos, shadows,
speech bubbles, click/hover, and all live data wiring are preserved.

## 2. Worker design rules

The Genesis Worker is a **rounded blocky** mascot on a 16×16 design grid,
scaled to any size. Original silhouette — inspired by minimalist pixel-mascot
energy, but copying no existing character or brand.

- **Rounded blocky body** — symmetric, clean, readable at 1× (`BODY` spans).
- **1px dark outline** (`#0a0c12`) — generated by expanding every body cell in
  4 directions. Guarantees a crisp silhouette on the dark floor at any scale.
- **Visor face** — a darker screen panel (`#11151f`) the eyes sit on. Gives the
  cute-tech / cyber-office read.
- **Expressive minimal eyes** — two eye-white blocks (`#eaf2ff`) with a
  department-accent shine. Eye *shape* changes per state (see §4).
- **Signature antenna** — a 1px stalk + a 2×2 accent dot. This is the brand
  mark every worker shares; it also carries the pulsing department glow.
- **Chest core light** — a 2×1 accent bar that pulses, signalling "alive".
- **Subtle department glow** — two layered low-opacity ellipses in the glow
  color. No blur filter (cheap with many workers on screen).
- **Top highlight** — a faint white pixel for a premium, rounded read.

Accessories (from `visualProfile.accessory`) layer on top: `crown` (CEO),
`shield` (risk), `book` / `clipboard` (research/HR). Anything else falls back to
the antenna.

**Avoid:** random pixel-people, generic NPC clutter, cheap retro jank,
bright childish colors.

## 3. Department visual system

Color **is** the department. The hue is readable the instant a worker appears.
Every hex below already exists in the Genesis palette (office zone colors /
seed agents) — see `GENESIS_TOKENS` in `src/lib/genesisWorkerDesign.ts`.

| Department (brief role) | Genesis departments | Primary | Accent | Signature |
|---|---|---|---|---|
| **CEO / Orchestrator** | Board Room | Gold `#ffd24a` | `#fff0b8` | Crown · calm motion |
| **Trading** | Market Room, Execution Desk | Green `#00ff9c` | `#3da9fc` | Fast motion · chart glow |
| **Risk** | Risk Office, Audit Office | Red `#ff4757` | `#ffb547` | Shield · alert posture |
| **Marketing** | Growth Room, Debate Room | Purple `#a855f7` | `#7c5cff` | Comms bubbles |
| **Research** | Strategy Lab, Genesis HR | Orange `#ffb547` | `#3da9fc` | Book · data work |
| **Memory** | Memory Archive | Blue `#1f6fb0` | `#22d3ee` | Archive glow |
| **Security / Watcher** | Special Ops | Gray `#5b6678` | `#22d3ee` | Patrol · night-mode |

Resolution order (`paletteForAgent`): the agent's own `visualProfile.primary`
wins if set (so seeded agents keep their established hues), otherwise the
department palette is used. The glow always comes from the department.

## 4. Animation system

Nine states, each a GPU-cheap CSS transform (`.gw-anim-*` in `src/index.css`).
`prefers-reduced-motion` disables all of them.

| State | Motion | Eyes | Driven by (AgentStatus) |
|---|---|---|---|
| `idle` | slow vertical bob | open | `idle`, `onboarding`, `waiting_review` |
| `walking` | fast bob + lean | open | `movementState === 'moving'` (overrides all) |
| `working` | tiny focused dip | focused | `working` |
| `thinking` | gentle tilt sway | focused | `thinking`, `learning`, `retraining` |
| `debating` | left↔right rotate | open | `debating` |
| `alert` | quick shake | wide | `warning` |
| `resting` | minimal slow squash | closed | `suspended` |
| `celebrating` | bounce + scale | happy `^^` | `promoted` |
| `blocked` | stepped jitter, dimmed | closed | `failed`, `fired` |

Mapping lives in `workerAnimForAgent()` / `eyeShapeForAnim()`. Movement state
always wins so a worker walking to a meeting *walks*, regardless of status.

## 5. Live office logic (no fake movement)

The HQ already routes real work to the office; the worker visuals simply read
that state. The data path is unchanged:

```
Founder command (CommandConsole / /api/command)
  → backend updates agent.status, agent.currentRoom, movementState, OrgStatus.focus/goal
    → genesisStore agents update
      → pixelLifeLoop / agentMovement move workers between rooms
        → AgentSprite renders the matching GenesisWorker animation
```

Because animation is a pure function of live `status` + `movementState`, founder
directives produce the right visuals automatically:

- **"Today is a holiday"** → most agents go `idle`/`suspended` in the cafeteria
  (resting animation, closed eyes); the Special Ops watcher stays active
  (patrol/working). No special-casing in the renderer.
- **"Goal: $1000 this week"** → more agents flip to `working`/`moving`/`debating`
  → more walk/work/debate animations, more room traffic, pulsing cores =
  visible urgency.
- **"Focus on marketing"** → Growth/Debate Room agents activate → a crowd of
  purple workers with comms motion.

The renderer never invents movement; it visualizes whatever the live system
already says is happening.

## 6. Economic / health visualization (existing hooks)

Company health is already surfaced by `MetricsPanel`, the treasury/capital
charts, and `OrgStatus`. The worker layer reinforces it ambiently: density of
`working`/`walking` workers = activity level, red `alert` workers = risk events,
gold celebrating workers = wins. No new economic UI is added here — the workers
are the *living* expression of metrics shown elsewhere.

- Per-department micro-props in rooms (chart glow at Market desks, archive
  shimmer in Memory) — additive only.
- Retire the unused `free-office-pixel-art` character PNGs once every surface
  uses Genesis Workers.

## 8. Reusable sprite design specification

The Genesis Worker is **fully reusable** — render one anywhere with:

```tsx
import GenesisWorker from './components/GenesisWorker';
import { paletteForAgent, workerAnimForAgent, eyeShapeForAnim } from './lib/genesisWorkerDesign';

const palette = paletteForAgent(agent);
const anim = workerAnimForAgent(agent.status, agent.movementState);

<svg viewBox="0 0 64 64">
  <GenesisWorker
    palette={palette}
    anim={anim}
    eye={eyeShapeForAnim(anim)}
    accessory={agent.visualProfile.accessory}
    x={6} y={2} size={52}
  />
</svg>
```

**Grid contract:** 16×16 units, scaled by `size/16`. Feet rest near grid row 14;
antenna occupies row 0. Body fill = `palette.primary`, trim/eyes/accessory shine
= `palette.accent`, glow = `palette.glow`, outline = `#0a0c12`.

**Spec invariants:**

- Only `GENESIS_TOKENS` colors. Never introduce a hue outside the palette.
- Outline is always `#0a0c12` (matches the HQ background → seamless silhouette).
- Eyes are the personality; keep them centered on the visor.
- One animation class per worker, set from live state — never random.
- No external image assets. The mascot is original and self-contained.
