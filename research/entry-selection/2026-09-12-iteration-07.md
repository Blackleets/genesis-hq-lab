## Hypothesis H07 — entry volume/liquidity conditioned abstention

**Hypothesis:** abstaining from v9 entries when contemporaneous market liquidity is weak may improve net expectancy by avoiding entries with worse execution economics and weaker breakout confirmation.

Volume/liquidity is selected next because the hosted futures runner already computes a causal quote-volume measure before opening each paper position and feeds it directly into the execution-cost/slippage model.

## Leakage / evidence-integrity audit

The runner obtains Binance klines before the signal and defines `quoteVolume(rows)` as the sum of kline quote-volume field `[7]` over the last six rows. On a qualified signal it calls `openPaperPosition(..., quoteVolume(rows), ...)`; that function persists the value as `entry_volume24h` on the trade. The same value is passed into `economics()` and `slippagePct()`, so it is available before entry and outcome-attributable without reconstructing post-outcome candles.

Important semantic caveat: despite the database column name `entry_volume24h`, the hosted runner value is **not 24-hour volume**. It is approximately six kline bars of quote volume (for v9 short profiles, six 5-minute rows). H07 therefore treats it only as the runner's contemporaneous liquidity proxy and does not reinterpret it as true 24h volume.
